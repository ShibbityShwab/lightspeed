### 2026-11-23: Pin one non-diverting WinDivert handle for the app lifetime and make Stop a true Stop

**Agent:** `rust-dev` + `qa-engineer`/qa-verifier + `release-scribe` (record); Lead integrated.
**Status:** Accepted — implemented on `fix/pinned-driver-1.12.5` (`9e73987` + updater fix `84e15c3`); 1.12.5 is a release candidate, tag/publish is the owner's gate.
**Rationale:** 1.12.1–1.12.4 hardened the close paths, and the 84-row real-driver matrix shows those close paths work (30/30 Stop→Optimize traffic cycles, 20/20 quit/relaunch, zero `FWP_E_IN_USE`). The historical failure — an orphaned WinDivert WFP provider that survives process exit — never reproduced on the old 1.12.3 build in a controlled run (30/30 cycles, 0 failure hits), so another close-path fix cannot be validated against it. Keeping one permanent non-diverting handle (filter `"false"`, Network, priority 0, normal flags) open means the driver is never unloaded by a Stop, so the unload/reload window that could leave a filter registered is not entered. Stop still closes every diverting backend (verified by per-id open/close counts), so no traffic or tunnel survives it: this is a true Stop, not a pause gate. The alternative — keeping a warm diverting handle — keeps intercepting/tunnelling on a Stop and was rejected.
**Impact:** `client/src/interceptor/windivert_handle.rs` (pin API, id-based instrumentation, per-kind counters, bounded `FWP_E_IN_USE` retry), `client/src/interceptor/mod.rs` (app-lifetime API; no-op on non-WinDivert builds), `client/src/engine.rs` (pin before the first start, keep across Stop, release only in `shutdown`/Drop), `client/src/app/{mod,commands,status}.rs`, `client-gui/src/app.rs` (Stop vs Quit/update paths), `client-gui/src/self_update.rs` (service stop before runtime-file copy, `finally` relaunch). Windows only; no config, wire, CLI or protocol change. Users: a normal Stop leaves WinDivert loaded; Quit releases the pin, but WinDivert 2.2 keeps the driver loaded until service stop/reboot (documented limitation, not boot-zero).
**Alternatives Considered:** another synchronous-close hardening patch (already shipped in 1.12.1/1.12.2; cannot be validated against an unreproduced fault); keeping a diverting handle open / pause gate (rejected: a Stop must not keep intercepting or tunnelling); stop the WinDivert service on every Stop (rejected: unload/reload is the churn, requires elevation on every stop and adds latency); fix only the self-update locked-file failure (rejected: does not address the data-plane design).
**Verification:** 84/84 real-driver matrix rows PASS on `84e15c3` (clean boot, real loopback relays + synthetic game traffic, exe SHA256 `F8ECE5824D674B186D2DB6C2D91703858F597B37B8A7FA3F317B4A6936EA8DFC`), zero `FWP_E_IN_USE`/failed opens/retries; evidence `wat/evidence/2026-11-23/task-107-matrix-84e15c3v2-20261123-115633/` and `wat/evidence/2026-11-23/task-107-release-report.md`.
