## 基本

### LightSpeed は本当に無料ですか？

はい。LightSpeed は LightSpeed Software License の下で、個人の非商用利用なら無料です。商用利用には有料ライセンスが必要です。[LICENSE](../LICENSE) を参照してください。自分のプロキシは小さな VPS で動かします（[デプロイガイド](../infra/README.md) を参照）。サブスクリプションも従量課金も有料プランもありません。

### LightSpeed を使うと BAN されますか？

いいえ。LightSpeed は、他のパケットキャプチャツールが使うのと同じ種類の OS レベルのネットワークドライバー（WinDivert/nftables/pfctl）を使っています。ゲームのファイル、メモリ、プロセスは変更しません。主要なアンチチート（EAC、VAC、BattlEye、Riot Vanguard）はいずれもこれを認めています。ゲームサーバーにはあなたの実際の IP アドレスが見えます。これは透過的なトンネルであって、VPN や匿名化ツールではありません。

### なぜインターセプターに root や管理者権限が必要なのですか？

カーネルレベルのパケット傍受には昇格した権限が必要です。VPN やファイアウォールに必要なのと同じ理由です。Linux では nftables/iptables を使います。macOS では pfctl を使います。Windows では WinDivert（署名済みカーネルドライバー）を使います。root がなくてもリダイレクトモード（`--game-server`）は使えます。

### どのプラットフォームに対応していますか？

| プラットフォーム | インターセプター | リダイレクトモード | GUI |
|----------|-------------|---------------|-----|
| Windows 10/11 | ✅ WinDivert | ✅ | ✅ egui |
| Linux | ✅ nftables/iptables | ✅ | ❌ CLI のみ |
| macOS | ✅ pfctl | ✅ | ❌ CLI のみ |
| Linux ARM64 | ✅ | ✅ | ❌ |

## 仕組み

### LightSpeed は実際にどうやって ping を下げるのですか？

LightSpeed は通信を速くするのでは **ありません**。パケットは光速を超えられません。やっているのは、利用可能な最速の経路へ通信を *先回りして振り向ける* ことで、混雑や無駄に長い回り道を避けます。

あなたの ISP は、*自分にとって* 一番安い経路にパケットを流します。多くの場合それは混雑していたり遠回りだったりします。LightSpeed は、ゲームサーバーの地域へバックボーンで直接つながった主要データセンターのプロキシを通してパケットを送ります。その経路が ISP の既定より短かったり混雑が少なかったりすれば、ping は下がり、安定します。よくある改善幅は 10〜40ms です。

### ping が上がってしまいました。なぜですか？

よくある理由は 2 つです。

1. **プロキシの場所が間違っている** - プロキシがゲームサーバーより自分の直通路より遠いと、余分なホップが遅延を加えます。これが最も多い原因です。目安として、プロキシは自分に近いものではなく **ゲームサーバー** に近いものを選んでください。
2. **接続の悪いプロキシ** - データセンターはすべて同じではありません。プロキシが役立つのは、そのデータセンターが主要なインターネットバックボーンやピアリングポイントの近くにある場合だけです。「正しい」都市にあっても、混雑した回線や家庭向け回線につながった安い VPS は、直通路より遅くなることがあります。

LightSpeed は与えられた経路しか最適化できません。置き場所の悪いプロキシを指定すれば ping は上がります。それは想定どおりの動作で、不具合ではありません。

### どのプロキシを選べばいいですか？

**ゲームサーバーの地域** に最も近いプロキシです。例:
- 米国西海岸のサーバーでプレイ → 米国西海岸のプロキシを選ぶ
- オーストラリアからシンガポールのサーバーでプレイ → シンガポールのプロキシを選ぶ
- 北米から EU のサーバーでプレイ → フランクフルトかロンドンのプロキシを選ぶ

### ルーティングの現実（BGP）について

実際のインターネットルーティングは **BGP**（Border Gateway Protocol）に支配されています。これは ISP やトランジット事業者が通信を引き渡すときに使う契約とポリシーです。あなたのパケットは直線的には進みません。BGP テーブルとピアリング契約が決めた経路に従い、事業者はコストやポリシーの理由で特定の経路を優先したり後回しにしたりします。

これがあなたにとって意味すること:

- プロキシが役立つのは、自宅回線の既定より *良い* BGP 経路にある場合だけです。ふつうは主要バックボーンやピアリングポイントの近くのデータセンターです。
- 「地図上で近い」がいつも「回線上で速い」とは限りません。
- 経路最適化ツール（LightSpeed を含む）は推定して経路を変えますが、物理的な経路は最終的に途中のネットワークが決めます。それはあなたにも LightSpeed にも制御できません。

### 自動検出はどのくらい速いですか？

ふつうはゲームサーバーに接続してから 1〜3 秒です。インターセプターは、同じ宛先への 3 パケットを 1.5 秒以内に確認してから固定します。

### LightSpeed はどこにリレーを追加するかをどう決めていますか？

プロキシは、ローカルに保存した DB-IP Lite データベースから IP アドレスの **国** を割り出します。これはセッション作成時に、クライアントの送信元アドレスとゲームサーバーの宛先アドレスの両方について、メモリ上で一時的に行われます。次に `(source_country, destination_country)` の組ごとにセッションを数え、ネットワークがどの地域の組み合わせが不足しているかを把握できるようにします。セルは少なくとも 3 セッションになるまで抑制され、公開統計は粗くまとめた地域ペアの件数（たとえば `mena-eu`）だけを持ちます。カウンターに生の IP は含まれず、配置パイプラインから生の IP が出力されることもありません。

## FEC（パケット修復）

### FEC とは何ですか？

前方誤り訂正（Forward Error Correction）です。リレーは、あなたのパケットと一緒に少量の冗長データ
（既定のブロックサイズで最大約 25%）を送ります。1 つ失われても、再送なしにパリティから
復元できるので、復元にゲームサーバーとの往復は不要です。

### 有効にする必要はありますか？

いいえ。パケット修復は既定で有効で、計測した損失に適応します。きれいな回線では実質的に
オーバーヘッドはなく、パリティは実際にパケットが落ちている間だけ増えます。（以前のビルドでは
手動トグルの「Reliability Shield」がありましたが、1.7 以降は適応ポリシーが常に制御します。）

## プロキシの運用

### プロキシノードはどうやって手に入れますか？

何もする必要はありません。LightSpeed はコミュニティリレーネットワークを既定で同梱しています。スポンサー資金による 8 台のリレー（ロサンゼルス、ニュージャージー、シンガポール、フランクフルト、東京、ムンバイ、マドリード、シドニー）を、クライアントが署名付きレジストリで自動で見つけます。レジストリの URL と運営者の公開鍵はクライアントに組み込まれているので、設定も設定ファイルも要りません。

別のレジストリを使いたい場合は、`--registry <url>` か `lightspeed.toml` の `[registry]` ブロックで上書きします。[コミュニティリレーネットワークガイド](community-network.md) を参照してください。

### 自分のプロキシを動かす必要はありますか？

いいえ。コミュニティネットワークが既定で、そのまま動きます。専用のリレーが欲しい場合もセルフホストは完全にサポートされています。任意の Linux VPS に軽量なプロキシ（RAM 約 500KB）をデプロイするだけです。[デプロイガイド](../infra/README.md) を参照してください。

### プロキシの費用はどのくらいですか？

コミュニティネットワークを使うなら無料です。セルフホストするなら小さな VPS が月数ドルで、プロキシバイナリは RAM を約 500KB しか使わないので、最小のインスタンスでも十分です。LightSpeed 自体には料金はありません。

### プロキシを友達と共有できますか？

はい。プロキシはクライアントごとのレート制限と認証を備え、複数の同時セッションに対応します。トークンは `proxy.toml` で設定します。

## トラブルシューティング

### 「No game traffic seen」

- ゲームが実際にサーバーに接続していることを確認する（メインメニューだけではだめです）
- 正しいゲームを選んでいるか確認する（`--game` フラグ）
- `--scan-processes` で実行中のゲームプロセスを一覧表示してみる
- サーバーが標準以外のポートを使っているなら、手動サーバーモード（`--game-server`）を使う

### 「Interceptor not available」

- Linux: root で実行しているか、nftables/iptables が入っているか確認する
- macOS: pfctl は標準ですが root が必要です
- Windows: `WinDivert64.sys` と `WinDivert.dll` が `.exe` の隣にあるか確認する

### パケットは送信されるが届かない

パケットはプロキシに届いていますが、応答がゲームに戻っていません。たいていはファイアウォールの問題です。LightSpeed はファイアウォールルールを自動で追加しようとします。それに失敗する場合は、`lightspeed` または `lightspeed-gui.exe` に対して受信 UDP ルールを手動で追加してください。

## プライバシー

### LightSpeed はゲームの通信を読んでいますか？

LightSpeed は、ルーティングのために UDP パケットのヘッダー（送信元と宛先の IP、ポート、サイズ）を見ます。ゲームの中身（プレイヤーの位置、チャットなど）はゲーム自身のプロトコルで暗号化されており、復号も記録もされません。詳しくは [プライバシーポリシー](privacy.md) を参照してください。

### テレメトリーはありますか？

テレメトリーは v1.6.5 以降 **既定で有効** です。匿名化した集計メトリクス（RTT のパーセンタイル、ジッター、FEC の統計、直接・リレー経由・削減分の遅延の数値）を、接続中のリレー（コミュニティかスポンサーのリレー、セルフホストなら自分のもの）の `/telemetry` エンドポイントへ送ります。IP アドレス、トークン、識別子、ゲームアカウントのデータは収集しません。セルは少なくとも 3 件の報告が集まるまで抑制されますが、この下限は報告の数を数えるもので、別人の数を数えるものではないので、3 人の異なる人が寄与したことを保証するものではありません。報告は平文の HTTP でポート 8080 に POST され、エンドポイントは認証されません。`--no-telemetry`、`lightspeed.toml` の `[general]` にある `telemetry = false`、または GUI の **「Share anonymous latency stats」** チェックボックスでいつでも切れます。[プライバシーポリシー](privacy.md) と [データ辞書](data-dictionary.md) を参照してください。

### プロキシは私の IP アドレスを保存しますか？

いいえ。プロキシは送信元 IP とゲームサーバーの宛先 IP を、パケットのルーティングと配置分析のための国を割り出すために、メモリ上で一時的に処理します。アドレス自体は保存しません。保存されるのは `(source_country, destination_country)` の組ごとの集計セッションカウンターで、セルごとに 3 セッションの下限があるため小さなセルは抑制され、公開統計は粗くまとめた地域ペアの件数だけを持ちます。配置のカウンターに生の IP は含まれず、配置パイプラインから生の IP が出力されることもありません。クライアントのテレメトリー契約は変わりません。リレーのアクセスログにはクライアント IP が含まれることがある点に注意してください。[プロキシは何を記録しますか？](#what-does-the-proxy-log) を参照してください。

### プロキシは何を記録しますか？

stdout に書かれる運用ログ（`RUST_LOG` で設定可能）には、クライアント IP、セッションの開始と終了の時刻、中継したバイト数が含まれることがあります。クライアント IP が現れるのはレート制限と不正利用の検出のためだけです。そのログはそのセッションを処理したリレー（コミュニティかスポンサーのリレー、セルフホストなら自分のもの）上にあり、外部に出力されず、配置のカウンターと結合されることもありません。保持期間はそのリレーのログ設定で決まります。[プライバシーポリシー](privacy.md) を参照してください。

## その他

### VPN と一緒に LightSpeed を使えますか？

たいていは使えません。どちらもネットワーク通信を傍受しようとするので衝突します。LightSpeed を使う前に VPN を切ってください。

### LightSpeed は Cloudflare WARP と一緒に動きますか？

はい。`--warp` を使うと、接続のプロキシ区間で WARP が有効になります。WARP はローカルの ISP ルーティングを 5〜10ms 削れることがあります。プロキシと組み合わせると効果が最大になります。

### 不具合はどこに報告しますか？

[GitHub で issue を作成してください](https://github.com/ShibbityShwab/lightspeed/issues)。OS、ゲーム、ログ出力（詳細ログには `RUST_LOG=debug` を付けて実行します）を添えてください。
