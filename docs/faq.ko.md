# 자주 묻는 질문

---

## 기본

### LightSpeed는 정말 무료인가요?

네. LightSpeed는 LightSpeed Software License에 따라 개인적, 비상업적 용도로 무료입니다. 상업적 사용에는 유료 라이선스가 필요합니다. [LICENSE](../LICENSE)를 참고하세요. 직접 소규모 VPS에서 프록시를 운영합니다(see [deployment guide](../infra/README.md)). 구독도, 사용료도, 유료 등급도 없습니다.

### LightSpeed 때문에 밴 당하나요?

아니요. LightSpeed는 다른 패킷 캡처 도구가 쓰는 것과 같은 종류의 OS 수준 네트워크 드라이버(WinDivert/nftables/pfctl)를 씁니다. 게임 파일이나 메모리, 프로세스를 수정하지 않습니다. 주요 안티치트 시스템(EAC, VAC, BattlEye, Riot Vanguard)은 모두 이를 허용합니다. 게임 서버는 여러분의 실제 IP 주소를 봅니다. 이건 VPN이나 익명화 도구가 아니라 투명한 터널입니다.

### 인터셉터에 왜 root/관리자 권한이 필요한가요?

커널 수준 패킷 가로채기에는 상승된 권한이 필요합니다. VPN과 방화벽에 같은 권한이 필요한 이유와 같습니다. Linux에서는 nftables/iptables, macOS에서는 pfctl, Windows에서는 WinDivert(서명된 커널 드라이버)를 씁니다. root가 없어도 리디렉션 모드(`--game-server`)는 쓸 수 있습니다.

### 어떤 플랫폼을 지원하나요?

| 플랫폼 | 인터셉터 | 리디렉션 모드 | GUI |
|----------|-------------|---------------|-----|
| Windows 10/11 | ✅ WinDivert | ✅ | ✅ egui |
| Linux | ✅ nftables/iptables | ✅ | ❌ CLI만 |
| macOS | ✅ pfctl | ✅ | ❌ CLI만 |
| Linux ARM64 | ✅ | ✅ | ❌ |

## 작동 방식

### LightSpeed는 실제로 어떻게 핑을 줄이나요?

LightSpeed는 트래픽을 더 빠르게 만들지 **않습니다**. 패킷은 빛의 속도를 넘을 수 없으니까요. 대신 트래픽을 쓸 수 있는 가장 빠른 경로로 *선제적으로 보냅니다*. 혼잡과 불필요하게 긴 우회를 피하는 것입니다.

여러분의 ISP는 *자기에게* 가장 저렴한 경로로 패킷을 보냅니다. 흔히 혼잡하거나 빙 돌아가는 경로입니다. LightSpeed는 게임 서버 리전과 직결 백본을 갖춘 대형 데이터 센터의 프록시를 통해 패킷을 보냅니다. 그 경로가 ISP 기본 경로보다 짧거나 덜 혼잡하면 핑이 내려가고 안정됩니다. 보통 10-40ms 정도 개선됩니다.

### 핑이 오히려 올라갔어요. 왜죠?

흔한 이유 두 가지입니다.

1. **프록시 위치가 잘못됨** - 프록시가 게임 서버에서 직접 경로보다 멀면 추가 홉이 지연을 더합니다. 가장 흔한 원인입니다. 경험 법칙: 내 위치가 아니라 **게임 서버**에 가장 가까운 프록시를 고르세요.
2. **연결이 나쁜 프록시** - 모든 데이터 센터가 같지는 않습니다. 프록시는 그 데이터 센터가 주요 인터넷 백본이나 피어링 교환점에 가까울 때만 도움이 됩니다. "맞는" 도시에 있지만 업스트림이 혼잡하거나 가정용 회선인 저렴한 VPS는 직접 경로보다 느릴 수 있습니다.

LightSpeed는 주어진 경로만 최적화할 수 있습니다. 위치가 나쁜 프록시를 지정하면 핑이 올라갑니다. 이건 예상된 동작이지 버그가 아닙니다.

### 어떤 프록시를 골라야 하나요?

**게임 서버 리전**에 가장 가까운 프록시입니다. 예를 들어,
- 미국 서부 서버에서 플레이 → 미국 서부 프록시 선택
- 호주에서 싱가포르 서버에서 플레이 → 싱가포르 프록시 선택
- 북미에서 EU 서버에서 플레이 → 프랑크푸르트/런던 프록시 선택

### 라우팅 현실에 대한 참고(BGP)

실제 인터넷 라우팅은 **BGP**(Border Gateway Protocol)가 지배합니다. ISP와 전송 사업자가 트래픽을 넘길 때 쓰는 계약과 정책입니다. 여러분의 패킷은 직선으로 가지 않습니다. BGP 테이블과 피어링 협약이 정한 경로를 따르며, 사업자는 비용이나 정책상의 이유로 특정 경로를 우선하거나 후순위로 두곤 합니다.

여러분에게 중요한 점은 이렇습니다.

- 프록시는 가정 회선의 기본 경로보다 *더 나은* BGP 경로에 있을 때만 도움이 됩니다. 보통 주요 백본이나 피어링 지점 근처의 데이터 센터입니다.
- "지도상 더 가까움"이 항상 "회선상 더 빠름"을 뜻하지는 않습니다.
- 경로 최적화 도구(LightSpeed 포함)는 추정하고 다시 경로를 잡지만, 물리적 경로는 결국 중간의 네트워크가 정합니다. 여러분도 LightSpeed도 그걸 통제하지 못합니다.

### 자동 감지는 얼마나 빠른가요?

보통 게임 서버에 접속한 뒤 1-3초입니다. 인터셉터는 1.5초 안에 같은 목적지로 가는 패킷 3개를 보고 나서야 목적지를 고정합니다.

### LightSpeed는 릴레이를 어디에 추가할지 어떻게 정하나요?

프록시는 로컬에 저장된 DB-IP Lite 데이터베이스에서 IP 주소의 **국가**를 도출합니다. 이는 세션 생성 시점에 클라이언트 출발 주소와 게임 서버 목적지 주소 양쪽에 대해 메모리에서 일시적으로 이뤄집니다. 그다음 `(source_country, destination_country)` 쌍별로 세션을 세어, 어느 지역 쌍이 부족한지 네트워크가 볼 수 있게 합니다. 셀은 세션이 3개 이상일 때까지 억제된 뒤 내보내지며, 공개 통계에는 거칠게 묶은 지역 쌍 카운트만 담깁니다(예: `mena-eu`). 카운터에는 원시 IP가 없고, 배치 파이프라인이 원시 IP를 내보내지도 않습니다.

## FEC(패킷 복구)

### FEC가 뭔가요?

Forward Error Correction, 순방향 오류 정정입니다. 릴레이가 여러분의 패킷과 함께 소량의 중복 데이터를
보냅니다(기본 블록 크기에서 최대 약 25%). 하나가 손실되면 재전송 없이 패리티로 복원할 수 있어,
복구에 게임 서버까지 왕복할 필요가 없습니다.

### 켜야 하나요?

아니요. 패킷 복구는 기본으로 켜져 있고 측정된 손실에 적응합니다. 깨끗한 회선에서는 실질적으로
오버헤드가 없고, 패킷이 실제로 드롭되는 동안에만 패리티가 올라갑니다. (이전 빌드에서는 "Reliability
Shield"라는 수동 토글이 있었지만, 1.7부터는 적응형 정책이 항상 담당합니다.)

## 프록시 운영

### 프록시 노드는 어떻게 구하나요?

아무것도 할 필요가 없습니다. LightSpeed는 커뮤니티 릴레이 네트워크를 기본으로 제공합니다. 후원사가 비용을 대는 8개의 릴레이(로스앤젤레스, 뉴저지, 싱가포르, 프랑크푸르트, 도쿄, 뭄바이, 마드리드, 시드니)를 클라이언트가 서명된 레지스트리를 통해 자동으로 찾아냅니다. 레지스트리 URL과 운영자의 공개 키가 클라이언트에 컴파일되어 있어 설정도, 구성 파일도 필요하지 않습니다.

다른 레지스트리를 쓰고 싶다면 `--registry <url>` 또는 `lightspeed.toml`의 `[registry]` 블록으로 덮어쓰세요. [커뮤니티 릴레이 네트워크 가이드](community-network.md)를 참고하세요.

### 직접 프록시를 운영해야 하나요?

아니요. 커뮤니티 네트워크가 기본이고 별도 설정 없이 바로 동작합니다. 전용 릴레이를 원한다면 자체 호스팅도 완전히 지원됩니다. 아무 Linux VPS에나 가벼운 프록시(약 500KB RAM)를 배포하세요(see [deployment guide](../infra/README.md)).

### 프록시 비용은 얼마인가요?

커뮤니티 네트워크를 쓰면 무료입니다. 자체 호스팅한다면 작은 VPS가 한 달에 몇 달러이고, 프록시 바이너리는 약 500KB RAM을 쓰므로 가장 작은 인스턴스로도 충분합니다. LightSpeed 자체에는 요금이 없습니다.

### 친구와 프록시를 공유할 수 있나요?

네. 프록시는 클라이언트별 속도 제한과 인증을 갖춘 다중 동시 세션을 지원합니다. `proxy.toml`에서 토큰을 구성하세요.

## 문제 해결

### "No game traffic seen"

- 게임이 실제로 서버에 접속되어 있는지 확인하세요(메인 메뉴가 아니라)
- 올바른 게임을 골랐는지 확인하세요(`--game` 플래그)
- `--scan-processes`로 실행 중인 게임 프로세스를 나열해 보세요
- 서버가 비표준 포트를 쓴다면 수동 서버 모드(`--game-server`)를 쓰세요

### "Interceptor not available"

- Linux: root로 실행 중인지, nftables/iptables가 설치되어 있는지 확인하세요
- macOS: pfctl은 내장이지만 root가 필요합니다
- Windows: `WinDivert64.sys`와 `WinDivert.dll`이 `.exe` 옆에 있는지 확인하세요

### 패킷은 보내지는데 전달되지 않음

패킷은 프록시에 도달하지만 응답이 게임에 도달하지 않습니다. 보통 방화벽 문제입니다. LightSpeed가 방화벽 규칙을 자동으로 추가하려고 시도합니다. 그게 실패하면 `lightspeed` 또는 `lightspeed-gui.exe`에 대해 인바운드 UDP 규칙을 직접 추가하세요.

## 개인정보

### LightSpeed가 게임 트래픽을 읽나요?

LightSpeed는 패킷을 라우팅하기 위해 UDP 패킷 헤더(출발/목적지 IP, 포트, 크기)를 봅니다. 게임 내용(플레이어 위치, 채팅 등)은 게임 자체 프로토콜로 암호화되어 있고 복호화하거나 기록하지 않습니다. 전체 [개인정보 처리방침](privacy.md)을 참고하세요.

### 텔레메트리가 있나요?

텔레메트리는 v1.6.5부터 **기본으로 켜져 있습니다**. 익명화된 집계 지표(RTT 백분위수, 지터, FEC 통계, 직접/릴레이/절감 지연 시간 수치)를 접속한 릴레이(커뮤니티 또는 후원 릴레이, 자체 호스팅이면 여러분의 릴레이)의 `/telemetry` 엔드포인트로 보냅니다. IP 주소, 토큰, 식별자, 게임 계정 데이터는 수집하지 않습니다. 셀은 보고가 3개 이상일 때까지 억제됩니다. 이 하한은 사람 수가 아니라 보고 수를 세므로 서로 다른 사람 3명이 기여했다고 보장하지는 않습니다. 보고는 평문 HTTP로 포트 8080에 POST되며 엔드포인트는 인증이 없습니다. `--no-telemetry`, `lightspeed.toml`의 `[general]` 아래 `telemetry = false`, 또는 GUI의 **"Share anonymous latency stats"** 체크박스로 언제든 끌 수 있습니다. [개인정보 처리방침](privacy.md)과 [데이터 사전](data-dictionary.md)을 참고하세요.

### 프록시가 제 IP 주소를 저장하나요?

아니요. 프록시는 출발 IP와 게임 서버 목적지 IP를 패킷 라우팅과 배치 분석용 국가 도출을 위해 메모리에서 일시적으로 처리합니다. 주소 자체는 저장하지 않습니다. 남는 것은 `(source_country, destination_country)` 쌍별 집계 세션 카운터이며, 작은 셀을 억제하기 위해 셀당 세션 3개를 하한으로 두고, 공개 통계에는 거칠게 묶은 지역 쌍 카운트만 담깁니다. 배치 카운터에는 원시 IP가 없고, 배치 파이프라인이 원시 IP를 내보내지도 않습니다. 클라이언트 텔레메트리 계약은 바뀌지 않았습니다. 릴레이 접속 로그에는 클라이언트 IP가 담길 수 있으니 참고하세요. [프록시는 무엇을 기록하나요?](#what-does-the-proxy-log)를 보세요.

### 프록시는 무엇을 기록하나요?

stdout에 기록되는 운영 로그(`RUST_LOG`로 구성 가능)에는 클라이언트 IP, 세션 시작/종료 시각, 릴레이한 바이트가 담길 수 있습니다. 클라이언트 IP는 속도 제한과 악용 탐지를 위해서만 거기에 나타납니다. 그 로그는 세션을 처리한 릴레이(커뮤니티 또는 후원 릴레이, 자체 호스팅이면 여러분의 릴레이)에 남고, 내보내지지 않으며, 배치 카운터와 결합되지도 않습니다. 보존 기간은 그 릴레이의 로깅 구성이 정합니다. [개인정보 처리방침](privacy.md)을 참고하세요.

## 기타

### VPN과 함께 LightSpeed를 쓸 수 있나요?

일반적으로는 안 됩니다. 둘 다 네트워크 트래픽을 가로채려 하므로 충돌합니다. LightSpeed를 쓰기 전에 VPN을 끄세요.

### Cloudflare WARP와 함께 동작하나요?

네. `--warp`를 쓰면 연결의 프록시 구간에 WARP를 켤 수 있습니다. WARP는 로컬 ISP 라우팅에서 5-10ms를 줄여줄 수 있습니다. 최대 효과를 보려면 프록시와 함께 쓰세요.

### 버그는 어디에 신고하나요?

[GitHub에 이슈를 열어 주세요](https://github.com/ShibbityShwab/lightspeed/issues). OS, 게임, 로그 출력을 포함하세요(자세한 로그는 `RUST_LOG=debug`로 실행).
