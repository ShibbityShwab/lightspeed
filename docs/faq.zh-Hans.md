## 基础

### LightSpeed 真的免费吗？

是的。按照 LightSpeed 软件许可，LightSpeed 对个人、非商业用途免费。商业用途需要付费许可，参见 [LICENSE](../LICENSE)。你自己在一台小型 VPS 上运行代理（参见[部署指南](../infra/README.md)）。没有订阅，没有使用费，没有付费档位。

### LightSpeed 会让我被封号吗？

不会。LightSpeed 使用的是和其他抓包工具同一类的操作系统级网络驱动（WinDivert/nftables/pfctl）。它不修改游戏文件、内存或进程。所有主流反作弊系统（EAC、VAC、BattlEye、Riot Vanguard）都允许这种做法。游戏服务器看到的是你的真实 IP 地址：这是一条透明隧道，不是 VPN 或匿名工具。 

### 为什么拦截器需要 root/管理员权限？

内核级的包拦截需要提权，VPN 和防火墙需要权限也是同样的原因。Linux 上它使用 nftables/iptables。macOS 上它使用 pfctl。Windows 上它使用 WinDivert（一个已签名的内核驱动）。没有 root，你仍然可以使用重定向模式（`--game-server`）。

### 支持哪些平台？

| 平台 | 拦截器 | 重定向模式 | 图形界面 |
|----------|-------------|---------------|-----|
| Windows 10/11 | ✅ WinDivert | ✅ | ✅ egui |
| Linux | ✅ nftables/iptables | ✅ | ❌ 仅 CLI |
| macOS | ✅ pfctl | ✅ | ❌ 仅 CLI |
| Linux ARM64 | ✅ | ✅ | ❌ |

## 工作原理

### LightSpeed 到底是怎么降低延迟的？

LightSpeed **不会**让流量跑得更快，数据包跑不过光速。它做的是*主动路由*，把你的流量放到当前可用的最快路径上，避开拥塞和不必要的绕路。

你的 ISP 会沿着对它*自己*最便宜的路径发送数据包，这条路径往往拥堵或绕远。LightSpeed 把你的数据包通过一台位于大型数据中心的代理转发，这个数据中心与各游戏服务器区域有直连骨干网。如果这条路径比 ISP 的默认路由更短或更不拥堵，你的延迟就会下降并变稳定。典型的改善幅度：10-40ms。

### 我的延迟反而升高了。为什么？

两个常见原因：

1. **代理位置不对**：如果代理离游戏服务器比你的直连路径更远，多出来的一跳会增加延迟。这是最常见的原因。经验法则：选择离**游戏服务器**最近的代理，不是离你最近的。
2. **代理的线路质量差**：不是所有数据中心都一样。只有当该数据中心挨着主要互联网骨干网或对等交换点时，代理才有帮助。一台位于"正确"城市但上行线路拥堵或属于家用宽带的廉价 VPS，可能比你的直连路由还慢。

LightSpeed 只能优化你给它的路由。如果你指给它一个位置糟糕的代理，延迟就会升高：这是预期行为，不是缺陷。

### 我该选哪个代理？

离**游戏服务器所在区域**最近的代理。例如：
- 在美西服务器上玩 → 选美西代理
- 从澳大利亚连新加坡服务器 → 选新加坡代理
- 从北美连欧服 → 选法兰克福/伦敦代理

### 关于路由现实（BGP）的说明

真实的互联网路由由 **BGP**（边界网关协议）决定：ISP 和传输服务商之间交接流量所依据的合同与策略。你的数据包不会走直线，它们沿着 BGP 表和互联协议决定的路径走，而且服务商出于成本或策略原因会经常给某些路由升优先级或降优先级。

这对你意味着什么：

- 只有当代理处在一条比你家宽带默认路由*更好*的 BGP 路径上时，它才有帮助，通常就是靠近主要骨干网或对等点的一处数据中心。
- "地图上更近"并不总是"线路上更快"。
- 路由优化工具（包括 LightSpeed）会估算并重新选路，但物理路径最终由中间的各个网络决定，这既不由你控制，也不由 LightSpeed 控制。

### 自动检测有多快？

通常在你连接游戏服务器后 1-3 秒。拦截器会观察 1.5 秒内发往同一目的地的 3 个数据包，然后锁定。

### LightSpeed 如何决定在哪里增加中继？

代理会从本地存储的 DB-IP Lite 数据库中解析 IP 地址的**国家**。这个过程发生在会话创建时，在内存中临时进行，对客户端源地址和游戏服务器目的地址都做一次。然后它按 `(source_country, destination_country)` 组合统计会话数，这样网络就能看出哪些区域对服务不足。某个统计单元在导出前，至少要有 3 个会话才会被输出，而且公开的统计只包含粗化的区域对计数（例如 `mena-eu`）。这些计数器不含原始 IP，投放流水线也不会导出任何原始 IP。

## FEC（数据包修复）

### 什么是 FEC？

前向纠错（Forward Error Correction）。中继会在你的数据包之外发送少量冗余数据
（默认块大小下最多约 25%）。如果有一个包丢了，可以不用重传、直接由校验数据重建，
所以恢复不需要到游戏服务器走一个来回。

### 我需要启用它吗？

不需要。数据包修复默认开启，并根据实测丢包情况自适应：线路干净时基本没有额外开销，
只有确实在丢包时校验比例才会升高。（早期版本提供过一个手动开关，叫"Reliability
Shield"；从 1.7 起，始终由自适应策略接管。）

## 运行代理

### 我该怎么获得一个代理节点？

什么都不用做。LightSpeed 默认自带社区中继网络：八台由赞助商出资的中继（洛杉矶、新泽西、新加坡、法兰克福、东京、孟买、马德里、悉尼），客户端会通过签名注册表自动发现它们。注册表 URL 和运营方的公钥都编译进了客户端，所以无需配置，也不需要配置文件。

如果你想使用别的注册表，可以用 `--registry <url>` 覆盖，或者在 `lightspeed.toml` 中加一个 `[registry]` 段。参见[社区中继网络指南](community-network.md)。

### 我需要自己运行代理吗？

不需要。社区网络是默认选项，开箱即用。如果你想要自己的专用中继，自建也完全支持：在任何 Linux VPS 上部署一个轻量代理（约 500KB 内存）。参见[部署指南](../infra/README.md)。

### 代理要花多少钱？

用社区网络的话，一分钱不花。如果你自建，一台小型 VPS 每月几美元，而代理二进制文件只占用约 500KB 内存，所以最小的实例也绰绰有余。LightSpeed 本身不收任何费用。

### 我能和朋友共用我的代理吗？

可以。代理支持多个并发会话，并带按客户端限速和认证。在 `proxy.toml` 中配置令牌。

## 故障排查

### "No game traffic seen"

- 确认你的游戏确实连接到了服务器（而不只是停留在主菜单）
- 确认你选对了游戏（`--game` 参数）
- 试试 `--scan-processes` 列出正在运行的游戏进程
- 如果你的服务器用了非标准端口，请使用手动服务器模式（`--game-server`）

### "Interceptor not available"

- Linux：确认你是以 root 运行，并且安装了 nftables/iptables
- macOS：pfctl 是内置的，但需要 root
- Windows：确认 `WinDivert64.sys` 和 `WinDivert.dll` 与 `.exe` 在同一目录

### 数据包发出去了但没有送达

你的数据包到达了代理，但响应没有回到游戏。通常是防火墙问题。LightSpeed 会尝试自动添加防火墙规则。如果失败，请手动为 `lightspeed` 或 `lightspeed-gui.exe` 添加入站 UDP 规则。

## 隐私

### LightSpeed 会读取我的游戏流量吗？

LightSpeed 会看到 UDP 数据包头部（源/目的 IP、端口、大小）以便路由。游戏内容（玩家位置、聊天等）由游戏自己的协议加密，不会被解密或记录。完整内容参见[隐私政策](privacy.md)。

### 有遥测吗？

从 v1.6.5 起，遥测**默认开启**。它会向你连接的中继（社区或赞助中继，如果自建就是你自己那台）的 `/telemetry` 端点发送匿名化的汇总指标（RTT 百分位、抖动、FEC 统计，以及直连/中继/节省的延迟数值）。不收集 IP 地址、令牌、标识符或游戏账号数据。某个统计单元至少要有 3 份报告才会输出；这个下限统计的是报告数，不是不同的人，所以它并不保证有 3 个不同的人贡献了数据。报告以明文 HTTP POST 到 8080 端口，该端点不进行认证。你随时可以用 `--no-telemetry`、`lightspeed.toml` 中 `[general]` 下的 `telemetry = false`，或者图形界面里的 **"Share anonymous latency stats"** 复选框把它关掉。参见[隐私政策](privacy.md)和[数据字典](data-dictionary.md)。

### 代理会存储我的 IP 地址吗？

不会。代理会在内存中临时处理你的源 IP 和游戏服务器的目的 IP，用来路由数据包并推导出国家以做投放分析。地址本身不会被存储。保留下来的是按 `(source_country, destination_country)` 组合统计的汇总会话计数器，每个统计单元有 3 个会话的下限，所以小的统计单元会被抑制，公开统计只包含粗化的区域对计数。投放计数器不含原始 IP，投放流水线不会导出任何原始 IP；客户端遥测合同保持不变。注意中继的访问日志可能包含客户端 IP；参见[代理会记录什么日志？](#what-does-the-proxy-log)。

### 代理会记录什么日志？

写到 stdout 的运维日志（可通过 `RUST_LOG` 配置）可能包含客户端 IP、会话起止时间和转发的字节数。客户端 IP 出现在那里只是为了限速和滥用检测。这些日志位于服务该会话的中继上（社区或赞助中继，如果自建就是你自己那台），不会被导出，也不会与投放计数器关联。保留时间由该中继的日志配置决定。参见[隐私政策](privacy.md)。

## 其他

### 我可以和 VPN 一起用 LightSpeed 吗？

一般不行，两者都会尝试截获网络流量，会互相冲突。使用 LightSpeed 前请先关掉 VPN。

### LightSpeed 能和 Cloudflare WARP 一起用吗？

可以。用 `--warp` 为连接中的代理这一段启用 WARP。WARP 可以为本地 ISP 路由省下 5-10ms。配合代理使用效果最好。

### 我该在哪里报告缺陷？

[在 GitHub 上提交 issue](https://github.com/ShibbityShwab/lightspeed/issues)。请附上你的操作系统、游戏和日志输出（用 `RUST_LOG=debug` 运行可以得到详细日志）。
